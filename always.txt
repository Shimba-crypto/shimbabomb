SHIMBABOMB ALWAYS RULES — read every session

GOALS:
- English-like SB that compiles to C, from-scratch GUI (Ketiwe X11), no heavy deps
- Small, fast, portable. Keep SB_STD_DIR and SB_SRC_DIR correct.

ALWAYS DO:
- After any src/*.c src/*.h std/*.sb change: rebuild and install
  gcc ... -o /tmp/sb_vX ... && cp /tmp/sb_vX ~/.local/bin/sb.vX.Y.Z && cp /tmp/sb_vX build/sb && cp VERSION ~/.local/share/shimbabomb/VERSION && cp std/*.sb ~/.local/share/shimbabomb/std/ && update wrapper ~/.local/bin/sb exec -a sb
- Update site/install.sh when install.sh changes: cp install.sh site/install.sh
- Keep Output/ fresh: after build, copy binaries/docs to /home/shimba/shimbabomb/Output/ if exists
- Bump VERSION file, rebuild, test `sb --help` shows new version
- Test `sb update` uses tags API, not releases/latest
- Run at least one .sb example: bring maths, lambda block, ketiwe if touched
- Commit with clear message, tag if release, push main --tags
- Keep sb.vX.Y.Z wrapper pointing to latest, not sb.real
- Preserve period terminator `.` in SB, and `and`/`or` as keywords

NEVER DO:
- Say "good catch" — just fix
- Leave VERSION and binary out of sync
- Push tag without testing sb --help and sb update

OUTPUT:
- /home/shimba/shimbabomb/Output/ must have latest sb binary, docs, installer if built
